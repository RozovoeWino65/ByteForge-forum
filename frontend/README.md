# ByteForge — фронтенд (MVP)

MVP клиентской части форума **ByteForge**: вход по никнейму, главная страница с
лентой постов и формой публикации, категории, профиль, удаление своих постов.

Технологии: чистый **HTML + CSS + JavaScript (ES-модули)**, без сборки и фреймворков.
Данные пока хранятся в `localStorage` (бэкенд в разработке), но весь доступ к данным
изолирован в одном слое `js/api.js` — переключение на реальный сервер делается одной строкой.

## Быстрый старт

Нужен любой статический сервер (ES-модули не работают по `file://`):

```bash
cd frontend
npx serve . -l 4173        # или: python3 -m http.server 4173
```

Открыть <http://localhost:4173>. Демо-данные подставятся автоматически.

Тесты:

```bash
cd frontend
npm install        # один раз: только jsdom для UI-тестов
npm test
```

## Что реализовано (MVP)

| Экран | Возможности |
| --- | --- |
| Вход `#/login` | Вход по никнейму, валидация (2–24 символа, буквы/цифры/`_`/`-`), аккаунт создаётся автоматически, сессия переживает перезагрузку |
| Главная `#/forum` | Лента постов (новые сверху), фильтр по категориям, счётчики постов, форма создания поста с валидацией и счётчиком символов, удаление своих постов (двойное подтверждение) |
| Профиль `#/profile` | Никнейм, аватар-инициал, список своих постов |

Дополнительно: адаптивная вёрстка (мобильный — категории горизонтальной лентой),
тёмная/светлая тема по системной настройке, состояния загрузки и пустой ленты,
тосты об успехе, тексты ошибок на русском, защита от XSS (весь пользовательский
текст выводится через `textContent`).

## Структура

```
frontend/
├── index.html            разметка обоих экранов (SPA, переключение по hash-роутам)
├── css/styles.css        все стили, CSS-переменные темы
├── js/
│   ├── config.js         настройки: режим API и адрес сервера
│   ├── api.js            слой данных: валидация + mock (localStorage) + REST-транспорт
│   ├── store.js          состояние приложения и сессия
│   ├── dom.js            DOM-хелперы (создание элементов, время, иконки)
│   └── app.js            роутинг и рендер экранов
└── tests/
    ├── api.test.js       тесты слоя данных (node:test)
    ├── dom.test.js       тесты форматирования времени
    └── ui.test.js        интеграционные тесты интерфейса (jsdom)
```

## Переключение на бэкенд

1. В `js/config.js` поставить `API_MODE: 'rest'` и указать `API_BASE_URL`.
2. Бэкенд должен отвечать по контракту из [`API.md`](./API.md).

Mock и REST имеют одинаковый интерфейс, поэтому `app.js` менять не нужно.
